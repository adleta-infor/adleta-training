How to Use This Guide

This is your session-by-session reference for training each Super User. For every session you will find: the M3 programs to open, what to set up in the test environment beforehand, exactly what to demo, and what to watch for. Run every session in the M3 test environment — never in production during training.

1

M3 Navigation and Getting Started

30 min
Programs to Open
M3 Main MenuCtrl+R (Quick Nav)MNS010 (User Settings)
Before the Session — Set Up
  • 📋Make sure the Super User has their M3 test login credentials and can reach the test environment URL.
  • 📋Have the portal open on your screen as well so you can reference the steps side-by-side.
What to Demo
  • ▶Log in to M3 test environment together. Show them the home screen layout.
  • ▶Press Ctrl+R — type PPS200, hit Enter. This is how you open any M3 program. Show them 2-3 programs this way.
  • ▶Show the standard function keys: F3 = Create new, F4 = Search/lookup, F5 = Refresh/save, Esc = Go back. These work the same in every program.
  • ▶Show how to use F4 in a field to open a lookup list. Demo on the Vendor field in PPS200.
  • ▶Show how to right-click a line to see Related options — this is how you navigate to sub-screens.
Watch For
  • ⚠️Super Users who are used to Windows apps will try to click through menus. Keep redirecting them to Ctrl+R and function keys.
  • ⚠️If they press Enter too fast and submit an empty form, show them how Esc backs out without saving.
✓ They can open any program with Ctrl+R, use F3/F4/F5/Esc correctly, and navigate back to the main menu.
2

M3 Data Structure — Items, Customers, Vendors

30 min
Programs to Open
MMS060 (Item Master)CRS610 (Customer Master)CRS620 (Vendor/Supplier Master)
What to Demo
  • ▶Open MMS060. Look up a real item number (use a common Adleta stocking item). Walk through the key panels: Description, Unit of Measure, Warehouse settings, Acquisition/Planning flags.
  • ▶Open CRS610. Look up a real customer. Show: payment terms, credit limit, ship-to addresses, invoice delivery method.
  • ▶Open CRS620. Look up a real vendor. Show: payment terms, bank/ACH info, EDI trading partner flag.
  • ▶Explain the relationship: a Customer Order (OIS100) links a Customer (CRS610) + Item (MMS060). A Purchase Order (PPS200) links a Vendor (CRS620) + Item (MMS060).
Tip: Use Adleta's real vendor and customer numbers from the test environment — it makes the data feel familiar and relevant to them.
✓ They can look up any item, customer, or vendor in M3 and identify the key fields (terms, status, unit of measure).

Planned PO Release

35 min
Programs to Open
PPS170 (Planned PO)PPS200 (Purchase Order)CRS620 (Vendor Lookup)
Before the Session
  • 📋Confirm with IT that the test environment has planned POs (MRP-generated) for Alan's buyer code. If not, ask Bravo to generate test planned POs before the session.
  • 📋Know Alan's buyer code in M3 test so you can filter PPS170 to his records.
What to Demo
  • ▶Open PPS170. Set Buyer = Alan's code, Warehouse = the main warehouse. Press Enter. Show the list of planned POs.
  • ▶Click into one planned PO. Walk through each field: item, quantity, vendor, suggested date. Explain that these are system-generated from reorder points — the buyer reviews and decides whether to release.
  • ▶Select 2-3 planned POs. Choose Release. M3 converts them to firm POs.
  • ▶Open PPS200 and show that the released POs now appear. Verify status = 15 (or your configured released status).
Watch For
  • ⚠️Alan may try to release every planned PO at once. Explain the review step — not every suggested PO should be released automatically.
  • ⚠️If a vendor is inactive, M3 will error on release. Show him how to check vendor status in CRS620 before releasing.
✓ Can filter PPS170 by buyer, review planned POs, release selected ones, and verify the released PO in PPS200.

    Pre-Receipts — PPS300

    30 min
    Programs to Open
    PPS300 (Pre-Receipt)
    What to Demo
    • ▶Open PPS300. Enter the PO number. Instead of entering received quantities, enter the expected shipment quantities from the supplier ASN or packing list.

    ✓ Understands the EDI flow (850 out → 856 in → 810 in), can verify EDI settings on a vendor, and can handle an EDI 810 match exception in APS100.
