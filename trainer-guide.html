How to Use This Guide

This is your session-by-session reference for training each Super User. For every session you will find: the M3 programs to open, what to set up in the test environment beforehand, exactly what to demo, and what to watch for. Run every session in the M3 test environment — never in production during training.

M3 H5 Navigation — Quick Reference (Post on the Wall)
Open Any Program
Click the search bar in the left panel → type the program code → Enter. Click ≡ first if the panel is closed.
Create a New Record
From a list view, click the + button in the toolbar. Fill in the required fields (yellow = required).
Search / Lookup a Field
Click the 🔍 lookup icon next to the field. Type part of the name or number, press Enter, click the result.
Add a Line / Save
Fill in the entry row at the bottom → click Add. When all lines are done, click Change to save the record.
Work With a Record
Right-click any row → Select (Ctrl+1) to use it, Change (Ctrl+2) to edit, Display (Ctrl+5) to view only.
Navigate Between Panels
Click Next (bottom right) to move forward, or click any panel tab at the bottom (B, E, F, G…) to jump directly.
Cancel / Go Back
Click the < back arrow at the bottom, or right-click → Cancel (F12) to exit without saving.
⚠️ Do NOT press F5
F5 refreshes the browser and loses unsaved work. Use the Change button to save. Use the < back arrow to go back.

Navigation and Core UI — Logging In and Getting Around

2 hours
Programs to Open
CRS610 (Customer Master)CRS620 (Supplier Master)MMS060 (Stock Balance)PPS200 (Purchase Orders)OIS100 (Customer Orders)
Before the Session — Set Up

  • 📋Have a test customer number, supplier number, and item number ready to use for demos (use real Adleta data from the test environment).
What to Demo
  • ▶Log in together. Point out: TST badge (top right = test environment), home screen Favorites and Recent, company/division at bottom right.
  • ▶Opening a program: Click the search bar in the left panel (≡ to open it if closed). Type CRS610, press Enter. Show them 3–4 programs this way. This is the only way to open programs in M3 H5.
  • ▶Multiple programs open: Open CRS610, then PPS200, then OIS100. Show the tabs at the top — all three are open at the same time. Click between tabs.
  • ▶Panel navigation: Open CRS610 and look up customer 001001. Point to the panel tabs at the bottom (E, F, G, H, J…). Click F (Details) — show CO type and Cust no. mand fields. Click J (Financial 1) — show payment terms and credit limits. Use Next to move forward.
  • ▶Right-click in a list: From the CRS610 list, right-click any row. Show: Select (Ctrl+1) = open/use it, Change (Ctrl+2) = edit it, Display (Ctrl+5) = view only. This menu appears in every M3 list.
  • ▶Lookup icon: In any field with a 🔍 icon, click it to search. Type part of a name, press Enter, click the result. Demo in the Customer field of OIS100/A.
  • ▶Add + Change buttons: Show OIS101 — the entry row at the bottom with the Add button adds a line. The Change button at the bottom saves the record. These replace the checkmark in older M3 versions.
  • ▶Set up a Favorite: navigate to a program, right-click the tab or use the star. Show it appears on the home screen.
  • ▶Show the issue log in Teams/SharePoint. Have them submit one test entry: program code, steps, question, business impact.
Watch For
  • ⚠️Anyone pressing F5 — it refreshes the browser and kills unsaved work. Address it immediately and show the Change button instead.
  • ⚠️Super users who try to double-click records — in H5 you right-click → Select/Change/Display. Correct this early or it will cause confusion in every module session.
  • ⚠️Anyone who can't find the left panel search bar — if the ≡ hamburger is collapsed they won't see it. Show them how to open it.
✓ They can open any M3 program by code, navigate panels, right-click to Select/Change/Display a record, use the lookup icon, and submit a complete issue log entry — all without coaching.

Terminology and Entity Crosswalk

1.5 hours
Programs to Open
CRS610 (Customer)CRS620 (Supplier)MMS060 (Stock Balance)OIS100 (Customer Order)PPS200 (Purchase Order)
Before the Session — Set Up
  • 📋Print the Terminology Crosswalk doc — have copies for every super user.
  • 📋Have a live customer order and a live purchase order visible in the test environment to reference.
What to Cover
  • ▶Walk the M3 entity map: Customer (CRS610), Supplier (CRS620), Item/Stock Balance (MMS060), Warehouse, Purchase Order (PPS200), Customer Order (OIS100), Invoice, GL Account. For each: primary program, department owner, who sets it up vs. who uses it daily.
  • ▶Review the Terminology Crosswalk — map Adleta terms to M3 terms. Examples: "vendor" = Supplier, "product/SKU" = Item number, "stock on hand" = On-hand in MMS060, "sales order" = Customer Order in OIS100.
  • ▶Trace Procure to Pay in M3: PO (PPS200) → Receiving (PPS300) → AP Invoice (APS100) → Three-Way Match → Payment (APS130).
  • ▶Trace Order to Cash: Customer Order (OIS100) → Shipment (OIS300) → AR Invoice → Cash Receipt (ARS110).
  • ▶Each super user explains one entity: what it is, which program, who owns it, why it matters to their department. No notes — verbal only.
Watch For
  • ⚠️Confusion between MMS060 (Stock Balance by location/lot) and item setup. MMS060 shows WHERE inventory is and in which lot — it is not the item configuration screen.
  • ⚠️Finance team members who are unfamiliar with the warehouse flow — they need to understand Procure to Pay end-to-end even if they only touch the AP end.
✓ They can explain any M3 entity in plain language — which program it lives in, who owns it, and why it matters. They can trace both the Procure to Pay and Order to Cash flows without help.
4

Foundation Mastery Check

1.5 hours
Programs to Open
Any 3 programs relevant to their module
Before the Session — Set Up
  • 📋Prepare one customer, one supplier, and one item lookup task for each super user using test data.
  • 📋Have the issue log open and ready — you will review all open issues from Weeks 1–2.
  • 📋Prepare your Ready / Ready With Coaching / Not Ready assessment sheet.
What to Assess
  • ▶Navigation practical: Ask each super user to open three programs relevant to their module using the search bar — no coaching. Watch for hesitation, wrong clicks, or going to the wrong panel.
  • ▶Record lookup practical: Ask them to find a specific customer, supplier, and item by number. Then ask them to name 2–3 key fields on each record (e.g., payment terms, status, unit of measure).
  • ▶Right-click practical: Open a list view (e.g., CRS610). Ask them to open a record for editing. Watch that they right-click → Change, not double-click.
  • ▶Entity explanation: Each super user explains one record type — what it is, which program, who owns it, why it matters — without notes.
  • ▶Teach-back (3–5 min): Each super user explains to the group how they would help a department user find the right screen, look up a record, and log an issue.
  • ▶Issue log review: Go through all open issues from fnd-1 through fnd-3. Assign owners. Resolve all access blockers before Week 3 module training begins.
Watch For
  • ⚠️Super users still pressing F5, double-clicking, or looking for Ctrl+R — these are H5 habits that will break in every module session. Do not pass them until these are corrected.
  • ⚠️Anyone with unresolved login or access issues — these must be resolved before module training starts or they will fall behind immediately.
Readiness decision: Mark each super user as Ready (proceed to module training), Ready With Coaching (proceed with a targeted follow-up on one specific gap), or Not Ready (requires one more foundation session before module training). Do not move a Not Ready super user into module training — they will struggle and slow the group.
✓ They can open three role-relevant programs without coaching, look up a customer/supplier/item and name key fields, right-click correctly, and complete a 3–5 minute teach-back. All access blockers resolved.
