Session 1 - Order Management / Sales

Manual Order Entry — Standard Net Terms (CL1)

60 min
Objective

Enter a standard customer sales order in M3 using order type C01.

Scenario

Customer 000382 (AAA EXPRESS WATER AND FIRE RES) calls in an order for 5 CT of item ARM51830031 (IMPERIAL TEXTURE 1/8 INCH TILE). Enter the order.

Practice Tasks
1. Open OIS300 and start a new order
  1. Open OIS300 (Customer Order. Open) from the left sidebar search.
  2. Click the + (New) button. OIS100/A opens.
  3. Enter Customer = 000382.
  4. Enter CO type = C01.
  5. Enter Req delivery dt = today's date.
  6. Click Next.
2. Review order defaults (OIS100/I)
  1. Confirm Payment terms = N30 (30 days net).
  2. Confirm Warehouse = CAR (Carrollton).
  3. Confirm Delivery method = OT (Our Truck).
  4. Add your name in Your ref 1 if desired.
  5. Click Next.
3. Enter the order line (OIS101)
  1. In the Item field enter ARM51830031.
  2. Enter Order qty = 5.
  3. Confirm U/M = CT.
  4. Verify Net price populates automatically from price list LP1.
  5. Click Add to save the line.
  6. Note the CO no (order number) assigned by M3.
Expected Outcomes
  • Sales order created in M3 with CO type C01.
  • Order line entered with correct item, quantity, and price.
  • CO number noted for follow-up.
Sign-Off Checklist
  • I can look up a customer in CRS610 and verify their terms, price list, and status
  • I can create a sales order header in OIS100 and record the assigned order number
  • I can add order lines in OIS101 with correct item, quantity (100 SQF), and UOM
  • I always verify pricing against the customer price list before saving
  • I know the process for getting a price override authorized before entering it
Knowledge Check
1. When you enter a customer number in OIS100, M3 automatically fills in:
  • Item prices only
  • Name, address, payment terms, and price list (correct)
  • Warehouse location and carrier
  • Nothing — you fill all fields manually
2. The customer PO number field is important because:
  • It is required to release the order
  • It prints on the invoice and packing slip for customer reference (correct)
  • It auto-populates the price list
  • It routes the order to the correct warehouse
3. If the price in M3 does not match what was quoted to the customer:
  • Override it immediately to match the quote
  • Document the discrepancy and get authorization before changing (correct)
  • Delete the line and re-enter with the correct price
  • Cancel the order and re-enter it

Customer Return — Creating a Return Order

60 min
Objective

Create a return/credit order in M3 for goods being sent back by a customer.

Scenario

Customer 000382 (AAA EXPRESS WATER AND FIRE RES) is returning 2 CT of item ARM51830031 due to damage. Create a return order using CO type C05.

Practice Tasks
1. Find the original order in OIS300
  1. Open OIS300 and search for customer 000382.
  2. Locate the original order containing the item being returned.
  3. Note the CO no of the original order.
2. Create the return order
  1. Click + (New) in OIS300. OIS100/A opens.
  2. Enter Customer = 000382.
  3. Enter CO type = C05 (Credit NoStkUpd).
  4. Enter Req delivery dt = today.
  5. Click Next.
3. Enter the return line and confirm
  1. In OIS101, enter Item = ARM51830031.
  2. Enter Order qty = 2 (the quantity being returned).
  3. Confirm U/M = CT.
  4. In Your ref 1 on OIS100/I, enter the original CO no for reference.
  5. Click Add and note the new credit order CO no.
Expected Outcomes
  • Return order created with CO type C05.
  • Original order referenced on the credit order.
  • Credit CO number noted.
Sign-Off Checklist
  • I always get manager authorization before entering a return in M3
  • I can open OIS390 and reference the original order number
  • I enter return quantity (50 SQF) with correct UOM and return date
  • I select the correct return reason code (CUSTCANCEL or other)
  • I record the return order number assigned by M3
Knowledge Check
1. Before entering a return in M3, you must first:
  • Check inventory availability
  • Get authorization from a sales manager (correct)
  • Create a new customer order
  • Call the supplier for a credit
2. The return reason code CUSTCANCEL is used when:
  • The product is defective
  • The wrong item was shipped
  • The customer cancelled after shipment (correct)
  • Too much product was shipped
3. After confirming a return order in OIS390:
  • You must manually create the credit memo
  • A credit memo is generated automatically (correct)
  • The customer receives a refund immediately
  • Finance must re-enter the return in ARS100
Session 3 - Order Management / Sales

Order Entry — Handling a Credit Hold

60 min
Objective

Understand what happens when a customer order is stopped due to a credit limit in M3.

Scenario

You enter an order for a customer who has exceeded their credit limit. M3 places a CO stop on the order. Learn what the stop looks like and who to contact.

Practice Tasks
1. Enter the order
  1. Open OIS300 and click + (New). OIS100/A opens.
  2. Enter Customer = 000382, CO type = C01.
  3. Enter Req delivery dt and click Next.
  4. Add an order line in OIS101 and click Add.
2. Identify the credit stop
  1. Return to OIS100/I (Generic Panel) for the order.
  2. Look at the CO stop field - a value of 3 means Credit limit stop.
  3. A CO stop prevents the order from advancing to picking and shipping.
  4. Do NOT release the stop without authorization from AR.
3. Escalate to AR
  1. Contact the AR team with the customer number, CO no, and order amount.
  2. AR will review the account and either release the stop or ask the customer to pay.
  3. Once released, the CO stop field will clear and the order can proceed.
  4. Add a note in Your ref 1 with the date and who approved the release.
Expected Outcomes
  • Credit stop identified on the order (CO stop = 3).
  • AR team contacted with order details.
  • Process for release understood.
Sign-Off Checklist
  • I can recognize a credit hold message when M3 blocks an order release
  • I know NOT to bypass, override, or work around a credit hold under any circumstances
  • I know the escalation path: Philip Jones or AR team removes holds — not me
  • I can locate the credit hold flag in CRS610 (view only)
  • I can add order notes documenting who I called, when, and what was said
Knowledge Check
1. When a credit hold blocks an order release, you should:
  • Change the payment terms to bypass the hold
  • Escalate to Philip Jones or the AR team — never bypass (correct)
  • Delete the order and re-enter under a different customer number
  • Approve it yourself if the amount is small
2. The credit hold flag on a customer record is located in:
  • OIS100 on the order header
  • CRS610 the customer master (correct)
  • APS100 the invoice entry screen
  • MMS060 the item master
3. Order notes documenting a credit hold must include:
  • The customer email address only
  • Who you called, when, what was said, and next steps (correct)
  • The GL account code for the order
  • The warehouse bin location

Will Call Order — Immediate Pickup

1.5 hours
Objective

Enter a will call order for a customer picking up at the Carrollton counter.

Scenario

Customer 000382 walks in and wants to pick up 3 CT of ARM51830031 today. Enter a will call order in OIS300 using CO type C01.

Practice Tasks
1. Create the will call order
  1. Open OIS300 and click + (New). OIS100/A opens.
  2. Enter Customer = 000382.
  3. Enter CO type = C01 (Bravo Normal/WC - WC stands for Will Call).
  4. Enter Req delivery dt = today.
  5. Click Next.
2. Set delivery method to will call (OIS100/I)
  1. On OIS100/I change Delivery method from OT (Our Truck) to WC (Will Call).
  2. Confirm Warehouse = CAR.
  3. Click Next.
3. Enter order line and notify warehouse
  1. In OIS101, enter Item = ARM51830031, Order qty = 3, confirm U/M = CT.
  2. Click Add and note the CO no.
  3. Notify the warehouse team so they can pick and stage the order for customer pickup.
Expected Outcomes
  • Will call order created with CO type C01.
  • Warehouse notified to pick and stage.
  • CO number given to customer.
Sign-Off Checklist
  • I can create a Will Call order in OIS300/OIS100
  • I know how to change the delivery method to Will Call
  • I can add Will Call charges to an order
  • I understand Will Call orders are issued at the delivery level — no load building required
  • I can verify the correct warehouse and Will Call route are assigned
Knowledge Check
1. Will Call orders are issued at which level?
  • Shipment level
  • Load level
  • Delivery level (correct)
  • Invoice level
2. Why do Will Call orders not require load building?
  • They are too small
  • Customer picks up at the warehouse — no truck loading needed (correct)
  • IT disabled it for Will Call
  • The warehouse skips this step
3. Where do you change the delivery method to Will Call?
  • CRS610
  • APS100
  • OIS300/OIS100 order header (correct)
  • PPS200
4. Will Call charges are added in which section of the order?
  • Item lines
  • Order header comments
  • Charges section (correct)
  • Delivery notes

Manual Order — Credit Card and COD Payment

1.5 hours
Objective

Enter a customer order where payment terms are different from the account default.

Scenario

A customer wants to pay COD or with a credit card instead of their standard net terms. Enter the order and change the payment terms in OIS100/I.

Practice Tasks
1. Create the order header
  1. Open OIS300 and click + (New). OIS100/A opens.
  2. Enter Customer number and CO type = C01.
  3. Enter Req delivery dt and click Next.
2. Change payment terms (OIS100/I)
  1. On OIS100/I, locate the Payment terms field (defaults to N30 for most customers).
  2. Click the search icon next to Payment terms to see available terms.
  3. Select the appropriate COD or prepay term.
  4. Note the Payment mtd AR field - confirm it matches the payment method (e.g., credit card, cash).
  5. Click Next.
3. Enter order line and confirm
  1. In OIS101, enter the item, quantity, and confirm U/M.
  2. Click Add.
  3. Note the CO no and communicate the updated payment terms to the customer.
Expected Outcomes
  • Order entered with non-standard payment terms.
  • Payment method confirmed on the order header.
  • CO number recorded.
Sign-Off Checklist
  • I can create a COD order in OIS100 with COD payment terms
  • I can verify the COD amount field matches the order total
  • I understand the driver collection process and the no-exceptions policy
  • I know the credit card handling procedure (M3 entry or terminal + receipt attachment)
Knowledge Check
1. On a COD order, the amount the driver must collect is:
  • Whatever the customer offers
  • The exact COD amount shown on the order in M3 (correct)
  • The deposit amount only
  • Determined at the door by the driver
2. The COD order amount flows automatically to:
  • The AR aging report only
  • The load manifest the driver carries (correct)
  • The GL directly without AP involvement
  • Birst reporting only
3. For credit card orders using a separate terminal, the terminal charge must:
  • Be entered in Birst for tracking
  • Exactly match the M3 order amount — receipt attached to order (correct)
  • Be approved by IT before processing
  • Be entered separately in APS100

A customer arrives to pick up their will call order. Confirm the order is ready, verify status, and understand how the order closes after pickup.

  2. Confirm quantity, item, and any special handling notes.

3. Verify order closes after pickup

  2. Status should advance to 90 (Closed) once all lines are delivered.
  3. Verify the transaction posts correctly in AR.

  • Customer pickup processed.
  • Order closes to status 90 after pickup.

2. When is payment collected for COD orders?
  • 30 days after invoice

3. If a COD customer wants will call, the delivery method should be set to:
  • OT

Session 7 - Order Management / Sales

Quote to Customer Order — Converting a Quote (N30)

1 hour
Objective

Create a quotation in M3 and convert it to a confirmed sales order when the customer accepts.

Scenario

Customer 000382 requests a price quote for 10 CT of ARM51830031. Create a quotation using CO type C04. When the customer accepts, convert it to a live order.

Practice Tasks
1. Create the quotation
  1. Open OIS300 and click + (New). OIS100/A opens.
  2. Enter Customer = 000382.
  3. Enter CO type = C04 (Quotation).
  4. Enter Req delivery dt and click Next.
  5. In OIS101, enter Item = ARM51830031, Order qty = 10, U/M = CT.
  6. Click Add and note the CO no (quote number).
2. Review the quote with the customer
  1. Locate the quote in OIS300 by filtering CO type = C04.
  2. Review all lines - confirm quantities and pricing are correct.
  3. Communicate the quote details and pricing to the customer.
3. Convert the quote to a sales order
  1. When the customer accepts, open the quote in OIS100.
  2. Go to Actions menu and select the option to copy or convert the order.
  3. Change CO type from C04 to C01 to make it a live order.
  4. Confirm the new order - note the new CO no.
  5. The original C04 quote should be closed or cancelled.
Expected Outcomes
  • Quotation created with CO type C04.
  • Customer accepted the quote.
  • Order converted to C01 with a new CO number.
Sign-Off Checklist
  • I can create a quote in OIS100 using the correct Quote order type
  • I can give a customer their quote number from the saved quote in OIS100
  • I can convert a quote to a firm CO — and know that inventory allocates at that step
  • I verify all lines, quantities, and pricing carried over correctly after conversion
Knowledge Check
1. When you save a quote in OIS100, inventory is:
  • Allocated immediately — stock is reserved
  • Not reserved — no inventory commitment until converted to a CO (correct)
  • Shipped automatically when the quote is approved
  • Billed to the customer immediately
2. The quote number given to the customer comes from:
  • The customer choosing a reference number
  • M3 assigning it when the quote is saved (correct)
  • The salesperson entering it manually
  • Finance approving the quote amount
3. When converting a quote to a CO, inventory is allocated:
  • When the quote was first created
  • When the customer calls to confirm
  • When you change the order type to CO in OIS100 (correct)
  • When the order ships from the warehouse

Drop Ship Order — Quote to Customer Order with Non-Cancel

1.5 hours
Objective

Process a drop ship order in M3 where goods ship directly from the supplier to the customer.

Scenario

Customer 000382 orders an item Adleta does not stock. The order will ship directly from the manufacturer. Enter a drop ship order using CO type C02.

Practice Tasks
1. Create the drop ship customer order
  1. Open OIS300 and click + (New). OIS100/A opens.
  2. Enter Customer = 000382.
  3. Enter CO type = C02 (Drop Ship Order).
  4. Enter Req delivery dt and click Next.
  5. On OIS100/I confirm the delivery address is the customer's address.
  6. Click Next.
2. Enter the order line
  1. In OIS101, enter the item number and quantity.
  2. Confirm the supplier for the item - M3 will route to the correct supplier.
  3. Click Add and note the CO no.
3. Confirm and communicate
  1. M3 will create a linked purchase order to the supplier automatically.
  2. Confirm both the sales order CO no and the linked PO number.
  3. When the supplier ships, the PO is received and the customer order closes.
  4. Communicate the expected ship date to customer 000382.
Expected Outcomes
  • Drop ship order created with CO type C02.
  • Linked supplier PO created automatically by M3.
  • Customer notified of expected ship date.
Sign-Off Checklist
  • I can create a drop ship order using line type 2 in OIS100
  • I understand that M3 automatically creates a linked PO for drop ship lines
  • I can verify the supply chain to confirm supplier and delivery address
  • I know when to use drop ship vs. ship from Adleta warehouse

1. Drop ship orders in M3 use which line type?
  • 0
  • 1
  • 2 (correct)
  • 3
2. In a drop ship order, goods are shipped by:
  • Adleta warehouse
  • A third-party logistics provider
  • The supplier directly to the customer (correct)
  • The customer picking up at Adleta
3. When you save a drop ship order line, M3 automatically creates a:
  • Delivery note
  • Purchase Order linked to the customer order (correct)
  • Credit memo
  • Journal entry
4. Drop ship is used when:
  • The item is in stock at Adleta
  • The customer wants will call
  • The product is not stocked in the Adleta warehouse and ships from supplier (correct)
  • The order is COD
