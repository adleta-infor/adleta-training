Session 1 - Finance — General Ledger

AP and GL Master Data — Account String Setup

60 min
Objective

Enter a manual journal entry in M3 using the GL Journal Voucher program.

Scenario

An accrual entry needs to be posted for the current period. Enter a manual journal voucher in GLS100 for Division AAA using FAM function 201 (USD Multi Function Entry).

Practice Tasks
1. Open GLS100 and select the FAM function
  1. Open GLS100 (Journal Voucher. Enter) from the left sidebar.
  2. The Select FAM Function screen appears - confirm Division = AAA.
  3. Select FAM function 201 (USD Multi Function Entry, voucher name GL01201).
  4. Click Apply or double-click 201 to open the journal entry form.
2. Enter the journal voucher header
  1. A new voucher header opens with Division AAA pre-filled.
  2. Enter the Accounting date (the period the entry should post to).
  3. Enter a Voucher text describing the purpose of the entry (e.g., Monthly accrual - [description]).
  4. The voucher number is assigned automatically by M3.
3. Enter the debit and credit lines
  1. On the journal lines panel, enter the first account number and debit amount.
  2. Enter the offsetting account number and credit amount.
  3. Confirm debit total equals credit total - M3 will not allow an unbalanced voucher.
  4. Click Save or Next to post the journal entry.
  5. Note the voucher number assigned - use GLS200 (Voucher. Display) to confirm it posted.
Expected Outcomes
  • Manual journal entry posted in GLS100 for Division AAA.
  • FAM function 201 (USD Multi Function Entry) used.
  • Voucher confirmed in GLS200 after posting.
Sign-Off Checklist
  • I can look up any GL account in GLS040 and read its type, description, and status
  • I understand Adleta's account number ranges (1XXXXX through 7XXXXX)
  • I know the cost centers for the departments I work with
  • I can assemble a valid Adleta account string from scratch
Knowledge Check
1. GL account master records are maintained in:
  • APS100
  • CRS610
  • GLS040 (correct)
  • MMS060
2. Adleta GL accounts beginning with 6XXXXX represent:
  • Revenue accounts
  • Asset accounts
  • Operating expense accounts (correct)
  • Liability accounts
3. If a new GL account is needed, you should:
  • Create it yourself in GLS040
  • Contact the CFO and IT — never create accounts without authorization (correct)
  • Copy an existing account and rename it
  • Ask IT to duplicate the nearest account number
Session 2 - Finance — General Ledger

Change GL Coding and Reverse an AP Invoice — APS200

45 min
Objective

Reverse a GL journal voucher that was posted in error.

Scenario

A journal entry was posted to the wrong accounting period or account. Reverse the original voucher in GLS100 using FAM function 101 (Autoreverse Voucher) or use Voucher. Reverse from the GL menu.

Practice Tasks
1. Find the incorrect voucher in GLS200
  1. Open GLS200 (Voucher. Display) from the left sidebar.
  2. Set Division = AAA and click Apply.
  3. Filter by Voucher number or Accounting date to locate the incorrect entry.
  4. Click the voucher to review the lines and confirm it is the entry to be reversed.
2. Reverse the voucher
  1. From GLS200, right-click the voucher and look for a Reverse option.
  2. Alternatively, open GLS100, select FAM function 101 (Autoreverse Voucher).
  3. Enter the original voucher number to reverse.
  4. Enter the reversal date - typically the first day of the next period.
  5. M3 creates a new voucher with all debit and credit lines swapped.
3. Verify the reversal posted
  1. Return to GLS200 and search for the reversal voucher.
  2. Confirm the reversal voucher has the same amounts as the original but opposite signs.
  3. If a correcting entry is also needed, enter it in GLS100 with FAM 201 (USD Multi Function Entry).
  4. Confirm the net effect on the affected accounts is correct.
Expected Outcomes
  • Incorrect voucher located in GLS200.
  • Reversal voucher posted using FAM 101 or Voucher. Reverse.
  • Correcting entry posted if required.
Sign-Off Checklist
  • I can navigate the chart of accounts in GLS040 and identify account types
  • I can distinguish between posting and non-posting accounts
  • I can run a GL inquiry in GLS910 for any account and period
  • I can drill into a transaction to find its source document
  • I can export GL inquiry results to Excel
Knowledge Check
1. A non-posting account in GLS040 means:
  • The account is closed
  • Transactions must be posted to detail accounts below it, not to this account directly (correct)
  • The account requires manager approval
  • The account is only used for reporting
2. In GLS910 you can drill into a transaction to see:
  • The supplier's contact details
  • The source document — journal entry, invoice, or payment — that created the posting (correct)
  • The budget for that account
  • The period close status
3. The correct way to find why a GL account balance changed in a period is:
  • Run a new journal entry
  • Open GLS910, enter the account and period, and review the transaction detail (correct)
  • Ask IT to run a report
  • Check the AR aging in ARS300
4. Account ranges in the Adleta chart of accounts are organized by:
  • Alphabetical order
  • Department name
  • Account type — assets, liabilities, equity, revenue, expense (correct)
  • Transaction date
Session 3 - Finance — General Ledger

Automatic Bank Reconciliation in M3

45 min
Objective

Display GL account balances and review period activity for a GL account.

Scenario

The controller asks you to pull the current period balance and activity for a GL account. Use GLS215 (GL Balance File. Display) to review the account.

Practice Tasks
1. Open GLS215 and set filters
  1. Open GLS215 (GL Balance File. Display) from the left sidebar (search 'GL Balance File').
  2. Set Period = current period (format YYMM, e.g., 2606 for June 2026).
  3. Set Division = AAA.
  4. Set the Account From and To range for the account you want to review.
  5. Click Apply.
2. Review the account balance
  1. GLS215 shows each account with Actual Period, Budget Period, and Variance columns.
  2. The Actual Period column shows the net activity posted to the account in the current period.
  3. To see individual transactions behind the balance, right-click the account row and select Related > Voucher lines or Transaction detail.
  4. Review the voucher lines to identify what transactions make up the balance.
3. Investigate discrepancies
  1. If the balance does not match expectations, drill into the voucher lines.
  2. Note the voucher numbers and accounting dates of any unexpected entries.
  3. Use GLS200 (Voucher. Display) to pull up the full voucher detail for any questionable entry.
  4. Escalate any unrecognized entries to the controller or accounting team.
Expected Outcomes
  • GL account balance reviewed in GLS215 for Division AAA.
  • Period activity confirmed.
  • Voucher detail drilled into via GLS200 for any discrepancies.
Sign-Off Checklist
  • I can navigate to the bank reconciliation menu and import a bank statement file
  • I can identify auto-matched items vs. unmatched exceptions on both sides
  • I can manually match an unmatched bank item to its book entry
  • I can record a bank fee as a journal entry in GLS100 to clear it from the reconciliation
Knowledge Check
1. After importing a bank statement, auto-matched items require:
  • Manual review and confirmation for each one
  • No action — M3 already matched them (correct)
  • A journal entry to post them
  • Finance director approval
2. A bank fee on the statement that has no book entry in M3 should be recorded as:
  • An AP invoice in APS100
  • Ignored until next month
  • A journal entry in GLS100 (correct)
  • A lockbox item in ARS110
3. Outstanding items on the bank side (no book entry) indicate:
  • A Birst reporting error
  • Transactions that may need investigation or timing differences (correct)
  • The reconciliation is complete
  • IT must reset the bank feed
Session 4 - Finance — General Ledger

AR Debit Note Write Off

1.5 hours
Objective

Process a period close checklist step - confirm all AP batches and GL journals are posted before close.

Scenario

It is month-end. Walk through the key M3 steps to confirm AP invoices are posted, GL journals are complete, and the period is ready to close in GLS910.

Practice Tasks
1. Confirm AP invoices are posted
  1. Open APS450 (Supplier Invoice Batch. Open), set Division = AAA, click Apply.
  2. Confirm no invoices remain in an unposted or error status.
  3. Open APS130 (Suppl Payment Proposal. Open) and confirm all payment proposals for the period are finalized.
  4. If any invoices need to post before close, process them now.
2. Confirm GL journals are complete
  1. Open GLS100 (Journal Voucher. Enter), Division AAA.
  2. Check for any saved but unposted journal vouchers.
  3. Open GLS200 (Voucher. Display), set Division = AAA, filter to current period, click Apply.
  4. Review the list to confirm all expected accrual and adjusting entries are present.
3. Run the period close in GLS910
  1. Open GLS910 (Year/Period. Close) from the left sidebar.
  2. Set Division = AAA and the period to close.
  3. Review any warnings M3 displays before closing.
  4. Confirm the close - once closed, no additional entries can be posted to that period without reopening.
  5. Notify the controller that the period is closed.
Expected Outcomes
  • AP invoices confirmed posted before close.
  • GL journals reviewed and complete in GLS200.
  • Period closed in GLS910 for Division AAA.
Sign-Off Checklist
  • I can locate a small open debit note for a test customer in ARS120
  • I can apply a write-off with the correct reason code and GL expense account
  • I verify the item is closed (balance zero) in ARS120 after posting
  • I can confirm the write-off transaction posted correctly in GLS200
Knowledge Check
1. Open customer balances and debit notes are viewed and managed in:
  • GLS200
  • APS100
  • ARS120 (correct)
  • CRS610
2. When applying a write-off, the two required selections are:
  • Supplier number and invoice number
  • Reason code and GL expense account (correct)
  • PO number and receipt number
  • Customer email and payment terms
3. After posting a write-off, you verify the GL transaction in:
  • PPS200
  • OIS100
  • GLS200 (correct)
  • ARS440
Session 5 - Finance — General Ledger

AR Tickler Notes — Collections Follow-Up

1 hour
Objective

Run a GL financial report in M3 to review the income statement or balance sheet.

Scenario

The controller needs a quick income statement for the current period. Run the GL financial report in GLS990 for Division AAA.

Practice Tasks
1. Open GLS990 and set report parameters
  1. Open GLS990 (Financial Report. Create) from the left sidebar.
  2. Set Division = AAA.
  3. Set the Period range to the current period.
  4. Select the report layout for the income statement (the controller or GL admin can tell you which layout to use).
  5. Click Apply or Run.
2. Review the report output
  1. GLS990 generates the financial report showing revenue, cost, and expense account balances.
  2. Review the totals for each section - Revenue, Cost of Goods Sold, Operating Expenses.
  3. Compare actual amounts to budget if the report includes a budget column.
  4. Note any accounts with unexpected balances or large variances to budget.
3. Export or print the report
  1. Use the Tools menu or print icon to export the report to Excel or PDF.
  2. Share the report with the controller or finance team.
  3. If an account balance needs investigation, use GLS215 (GL Balance File. Display) to drill into the detail.
  4. Document any variances or items requiring follow-up before the next leadership review.
Expected Outcomes
  • Financial report run in GLS990 for Division AAA.
  • Income statement reviewed for current period.
  • Variances identified and escalated as needed.
Sign-Off Checklist
  • I can work the daily tickler queue in ARS440
  • I review a customer's full AR aging in ARS120 before calling
  • Every call note includes: contact name, date, amount promised, next follow-up date
  • I set follow-up dates so customers never fall through the cracks
  • I know the escalation path: 3 unanswered calls → manager authorization → credit hold in CRS610
Knowledge Check
1. The tickler queue in ARS440 shows:
  • All open AP invoices for the period
  • Today's AR collection follow-ups that are due (correct)
  • All unmatched lockbox items
  • Birst dashboard alerts
2. A complete call documentation note must include:
  • Customer email address only
  • Contact name, date, amount promised, and next follow-up date (correct)
  • The salesperson name and territory
  • Only the invoice number and amount due
3. After 3 calls with no payment, the next step is:
  • Write off the balance immediately
  • Notify management to authorize a credit hold in CRS610 (correct)
  • Call every day until paid
  • Email the customer's CEO directly
